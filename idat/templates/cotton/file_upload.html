{% comment %} Encrypted upload (default): the file never leaves the browser before saving. It is checked (type, max. size, not empty), hashed, AES-GCM encrypted and kept in IndexedDB; only its metadata is submitted. States: Empty, Encrypting, Stored, Missing (metadata exists but the file is not in this browser, e.g. other tab or device), Error (client-side validation). Props: field Django BoundField (:field="form.x"): name, id, label, required, help_text and errors; from a widget that renders value / types / accept / max_size (the DSA40 wizard's ClientFileWidget) also the metadata, accepted types and max. size label label text without a form name name of the submitted metadata input without a form id id of the file input without a form; defaults to name value metadata JSON ({name, size, type, sha256}) without a form accept accepted extensions without a form, e.g. ".pdf,.docx" types JSON {extension: mime type} without a form max-size max. size in bytes without a form hint second line in the dropzone; default from the field: "PDF or DOCX · max. 10 MB" required boolean, without a form (shows the asterisk) help-tip help-panel tip id; shows the help icon plain boolean: a normal file input (Django FileField) submitted with the form instead of the encrypted ClientFile flow, e.g. a platform reply in the case tracker. The form needs enctype="multipart/form-data". Type (accept) and max-size are checked in the browser; pass hint for the second dropzone line. No Encrypting / Missing states and no encryption helper. The encrypted mode needs a clientFile Alpine component on the page (the DSA40 wizard provides it; the gallery has a stand-in). Plain uploads use plainFile from main.js. Drop a file on the dropzone or click it. {{ attrs }} go on the file input; class goes on the wrapper.
